FormFlow01 / Problem

Problem statement

Task definition and constraints

Develop a computer-vision-based system that captures freehand sketches through hand gestures and combines multiple 2D views (Front, Top, and Side) to reconstruct an approximate 3D representation without conventional CAD modelling.

Input

  • Monocular RGB webcam, no depth sensor
  • No markers, gloves or wearables
  • Unconstrained distance: laptop to across-the-room

Output

  • Watertight triangle mesh (OBJ / binary STL)
  • Interactive 3D scene
  • Approximate shape, for ideation

Constraints

  • No custom model training
  • Interactive frame rate on commodity hardware
  • Robust to jitter, occlusion, bystanders

FormFlow09 / Frame Pipeline

Per-frame processing pipeline

Every video frame passes through the same sequence; each stage has a unit-tested contract.

video frame -> RoiPlanner.plan() crop square ROI around hands -> HandLandmarker.detect 21 landmarks x N hands + 21 world landmarks (m) -> PoseLandmarker (opt.) wrist / elbow hint -> dedupeDetections() merge duplicate hands -> HandTracker.step() identity, roles, grace -> HandTrack.step() decode + condition cursor -> Mapper.map() image -> screen (isotropic) -> Controller.update() state machine -> Sketch (tools, camera) commit items -> SceneView.render() WebGL

Design rules

  • Normalised units everywhere: image fractions, palm-relative ratios
  • Time is passed in (seconds), never read from a clock, so tests are deterministic
  • Stages fail soft: lost hand cancels the stroke, never invents points
  • GPU delegate first, CPU fallback on failure
FormFlow10 / Hand Detection

Hand detection and identity tracking

Raw detections flicker, duplicate and swap labels. The tracker makes them usable.

WhatTurns noisy detections into two stable hands with roles.WhyRaw labels flicker, duplicate and swap, which would break every gesture.For whomThe user, whose hands must not be confused with bystanders.
ParameterValue
numHands4 (select user's 2)
Detect / presence / track conf.0.6 / 0.5 / 0.6 (0.35 far)
minPalm (wrist to MCP9)0.035 of image height
appearFrames3 consecutive frames
vanishGrace0.25 s (0.5 s with wrist)
matchRadius3.5 palms
Handedness vote window10 frames
Duplicate: wrist dist.< 0.6 palm

Algorithms

  • Identity by position (nearest within matchRadius); handedness label only votes
  • Duplicate removal: sort by score then size, drop detections whose wrists are within 0.6 palm
  • User hands: largest palm wins, +30% if near previous main hand; bystanders are smaller
  • Second hand accepted if opposite label and size ≥ 0.55, or same label, ≥ 0.15 apart and ≥ 0.70
  • Roles: main = dominant side, second = other
FormFlow11 / Small Hands

Small and distant hands: zoom-and-follow ROI and forearm hint

The palm detector runs on a downscaled image, so a hand covering ~3% of a wide shot is missed.

WhatCrops the frame around the hands and uses the arm as a second cue.WhyThe palm detector misses hands that cover only a few pixels.For whomUsers at a distance or on a projector setup.
crop size s = max(span_x/aspect, span_y) + reach * palm reach = 9 palm sizes, s in [0.30, 1.0] crop centre eased: c += 0.35 (c_target - c) full-frame scan every 20 frames full frame if no hand for 0.6 s landmarks back to full frame: x = roi.x + x_crop * roi.w y = roi.y + y_crop * roi.h

Why and how

  • A square crop keeps the aspect ratio, so back-mapping is one scale and one offset
  • Periodic full-frame scan finds a second hand or a new user
  • Pose model supplies wrist (15/16) and elbow (13/14), visibility ≥ 0.4
  • A hand that vanishes next to a known wrist is held longer and re-acquired where the arm went
  • Small hands: smoother cursor (cutoff scaled by palm/0.08), debounce 3 frames below palm 0.03
FormFlow12 / Gesture Decoding

Gesture decoding

Scale- and rotation-invariant features from the 21 landmarks; world (metric 3D) landmarks are preferred.

WhatClassifies pinch, grab, fist and peace from landmark ratios.WhyPalm-relative, rotation-proof features work at any distance and angle.For whomEvery user; thresholds adapt to their hand.
palm = |wrist - middle_MCP| rI = |thumb_tip - index_tip| / palm rM = |thumb_tip - middle_tip| / palm reach(i) = |lm[i] - wrist| curled(f) : reach(tip) < reach(pip) extended(f) : reach(tip) > 1.08 * reach(pip) fist = all 4 fingers curled peace = index, middle extended; ring, pinky curled; min(rI, rM) > 1.3 * on pinch = !fist && rI < th && rI <= 1.15 * rM grab = !fist && !pinch && rM < th && rM < 0.87 * rI

Robustness

  • Hysteresis: th = on (0.30) to enter, off (0.45) to leave
  • Debounce: pinch/grab 2 frames, fist/peace 3 frames
  • Priority: fist > pinch > grab; peace excludes fist
  • World landmarks are rotation-invariant: in image space a sideways hand shrinks the thumb-index gap by cos(theta) and fakes a pinch
  • Thresholds personalised in practice mode from median open and pinched ratios
FormFlow13 / Cursor Conditioning

Cursor signal conditioning

The pointer must land where the user aimed, not where noisy fingertips drifted while closing a pinch.

WhatFilters the pointer and compensates for finger drift.WhyPrecision drawing needs the stroke to start where the user aimed.For whomAnyone drawing; shaky hands benefit most.
One-Euro filter (per axis pair) tau = 1 / (2*pi*fc) alpha = 1 / (1 + tau/dt) dx^ = alpha_d * (x - x_prev)/dt + (1 - alpha_d) * dx^ fc = fc_min + beta * |dx^| x^ = alpha * x + (1 - alpha) * x^_prev fc_min = 1.0 * k, k = clamp(palm/0.08, 0.3, 1) beta = 6, d_cutoff = 1 palm anchor: cursor = palm_point + lowpass(offset) a = 0.35 (0.2 if palm < 0.04) glitch gate: jump > 0.18 image frac -> reject (max 3 consecutive frames) grasp latch: on pinch onset rewind 0.15 s, hold 0.08 s; on release rewind 0.10 s, hold 0.08 s freeze 0.3 s after release (controller)

Effect

  • Slow motion: heavy smoothing removes jitter
  • Fast motion: cutoff rises with speed, so no lag
  • Fingertips jitter more than the wrist, so the pointer follows the palm and only low-passes the finger offset
  • Latch removes the small cursor drag caused by closing the fingers, and the drift when they open
FormFlow14 / Mapping & Calibration

Screen mapping and calibration

Same physical movement should move the cursor equally on both axes, at any distance.

WhatMaps the hand reach area to the full screen and tunes thresholds.WhyThe same movement must feel identical on both axes and at any range.For whomDifferent setups: laptop webcam versus room camera.

Isotropic reach mapping

  • Reach region = box in image fractions mapped onto the whole screen
  • Camera pixels are not square in these units, so the region is adjusted: width * camAspect : height = screenAspect
  • Grow the short axis if it fits in the image, else shrink the long axis
  • Presets: near [0.12 0.10 0.88 0.80], medium, far [0.38 0.32 0.62 0.68], auto

Calibration

  • Reach calibration: hold at two opposite corners for 1.0 s, motion < 0.012 image fraction, minimum span 0.05
  • Practice mode: pinch and fist each held 0.5 s
  • Personal thresholds: on = c + 0.30 (o - c); off = max(on + 0.08, c + 0.50 (o - c)) with o = median open ratio, c = median pinched ratio; rejected if o < c + 0.2
  • Far / auto ranges lower detector confidence to 0.35
FormFlow15 / Controller

Interaction state machine

Maps hand frames to sketch actions. A mouse generates identical frames, so every path is testable.

WhatDecides what each hand frame means as an action.WhySeparating draw and navigate hands avoids accidental edits.For whomThe user; a mouse works identically for testing.
ConditionAction
main pinch + second pinchZoom: dist = dist0 * d0 / d, clamp [2.2, 9.0], eased 0.35
second fistOrbit (yaw, pitch) with inertia, decay 0.25 s
second peacePan, ignore motion < 1 px
main pinch on HUDPress button (consumed, no stroke)
main pinch in sceneBegin stroke or shape, add points, commit on release
main grab in scenePick nearest item, drag, commit on release
hand lost mid-gestureCancel gesture, no points invented

Details

  • Release trim: last 0.10 s (draw) / 0.15 s (drag) of motion dropped, so opening the fingers cannot kink the stroke
  • Input frozen 0.3 s after release
  • Navigation takes priority; a stray stroke gives way to zoom
  • Mouse: left = pinch, Shift+left = grab, right = fist, middle = peace
FormFlow16 / Sketch Engine

3D sketch engine

Pure logic, no DOM or WebGL. The renderer only reads its state.

WhatHolds the scene, camera, tools and undo history.WhyKeeping it free of DOM and WebGL makes it testable and exact.For whomDevelopers and the renderer that draws it.
world: X right, Y up, Z toward viewer workspace cube [-1, 1]^3, points clamped to +-1.2 camera: yaw, pitch, dist, target offset = dist * [cos(p) sin(y), sin(p), cos(p) cos(y)] FOV = 2 * atan(1 / (2 * 1.35)) = 40.6 deg (identical to the Three.js PerspectiveCamera) cursor -> 3D: unproject pixel to a ray, intersect the "glass" plane at the current depth depth step 0.2, snap step 0.1, stroke spacing 0.03 picking: point-to-segment distance in screen px d = |p - (a + t(b-a))|, t = clamp(((p-a).(b-a))/|b-a|^2, 0, 1)

Tools

  • Flat: freehand, line, rectangle, circle (40-segment ring)
  • Solids: cube, sphere, cylinder, cone, pyramid, all convex
  • Outward winding by construction: each triangle oriented away from the centre
  • Move, Scale, Undo (operation log)
FormFlow17 / Orthographic Workspace

Three-plane orthographic workspace

Drawing directly on projection planes makes every outline a true silhouette, with no unprojection ambiguity.

WhatLets the user draw directly on Front, Side and Top planes.WhyOutlines drawn on projection planes are true silhouettes.For whomUsers who think in engineering views.
+-----------+-----------+ | TOP | PREVIEW | | (x, z) | 3D hull | +-----------+-----------+ | FRONT | SIDE | | (x, y) | (z, y) | +-----------+-----------+ Front looks along Z key z Side looks along X key x Top looks along Y key y scale = min(cw, ch) / (2 * 1.35) px per world unit, identical in all three cells

Plane classification

  • An outline lies on the axis a whose coordinate range < 0.02
  • Exactly one flat axis, other two ranges > 0.06, else rejected (oblique or sliver)
  • Shared axes: Front+Top share X, Front+Side share Y, Top+Side share Z
  • Live dimension check with 0.15 tolerance in the workspace
FormFlow18 / Visual Hull

Visual hull reconstruction

Each silhouette extruded along its viewing ray certainly contains the object. Their intersection is the tightest bound from these views.

WhatIntersects extruded silhouettes into a 3D occupancy volume.WhyIt is the classical, explainable way to get 3D from outlines.For whomUsers wanting a solid from simple drawings.
1. collect closed outlines; auto-close gaps < 0.25 (path length >= 0.5) 2. per view: bbox, extent, centre 3. per axis: target = mean over views measuring it 4. affine align each view: v' = (v - ctr_m) * (ext_t / ext_m) + ctr_t 5. grid: L = 1.1 * max(ext), h = L / n, n = 64 6. rasterise: even-odd scanline fill at voxel centres, union of outlines per view 7. occupancy (3 masks): occ[i,j,k] = Mf[i,j] AND Ms[k,j] AND Mt[i,k] 8. largest 6-connected component (iterative DFS) 9. IoU(mask_view, projection(occ)) per view

Properties

  • Complexity O(n3): 262,144 voxels at n = 64 (48 while drawing live)
  • Two views fix all three dimensions; one view is extruded to thickness max(0.3, 0.5 * min other extent)
  • Deterministic, explainable, no training data
  • IoU close to 1 means the hull explains the drawings
  • Cannot recover concavities
FormFlow19 / Consistency & Alignment

Cross-view consistency

Hand-drawn views never agree exactly. The system aligns them, and warns when they disagree too much.

WhatAligns shared dimensions and flags disagreement.WhyHand-drawn views never agree exactly; silent errors would mislead.For whomThe user, who gets a warning instead of a bad model.
spread_a = max(ext) / min(ext) over views seeing axis a warn if spread_a - 1 > 0.35 message: "% differs between views" = 1 - 1/spread_a align (default): stretch + shift each view so every shared axis has the mean extent and mean centre axis measured by: X width : front.u , top.u Y height: front.v , side.v Z depth : top.v , side.u

Failure handling

  • No overlap between masks: explicit reason, no empty mesh
  • Multiple pieces: largest kept, count reported
  • Open or oblique outlines are counted and reported to the user
  • Single view: warns that the shape is extruded
  • Re-edit loop: change a view and rebuild
FormFlow20 / Meshing

Voxel grid to triangle mesh: surface nets

Avoids the blocky look of raw voxels and the lookup tables of marching cubes.

WhatConverts voxels to a smooth watertight mesh.WhyRaw voxels are blocky and cannot be exported or printed.For whomAnyone exporting to a slicer or CAD tool.
pad grid by 1 empty voxel (surfaces always closed) F = occupancy (0/1) as float soften: separable [1 4 1]/6 blur on x, y, z iso level 0.5 for every cell with mixed corner signs: vertex = mean of linear edge crossings t = (0.5 - f_a) / (f_b - f_a) for every sign-changing grid edge: emit quad of the 4 neighbouring cell vertices (2 triangles, flipped if the inside is on the far side) if signed volume < 0: flip all triangles

Output

  • Watertight, consistently wound mesh
  • Volume from signed tetrahedra sum
  • Triangle count and size reported in the panel
  • Export: ASCII OBJ (5 decimals) and binary STL (80 B header, 50 B per triangle, normal from cross product)
FormFlow21 / Image Silhouette

Silhouette extraction from a reference photo

Classical image processing to turn a photographed or scanned object into a closed outline for a view.

WhatTraces the outline of an object in a picture.WhyLets a real object seed a view instead of hand drawing.For whomUsers with a photo or scan of the object.
pixels (RGBA) -> mask auto : |colour - median(border)| / sqrt(3) > t t = max(Otsu(histogram), 18) (alpha > 127 for cut-outs) dark / light : luminance vs Otsu threshold -> morphological closing: erode(dilate(mask)), 3x3 -> connected components (4-neighbour) -> keep largest, fill holes (flood from border) -> boundary walk, clockwise, pixel corners -> Douglas-Peucker, eps = 0.012 * scale -> closed outline in [0, 1] picture coordinates

Algorithms

  • Otsu: threshold maximising between-class variance wB wF (mB - mF)2
  • Luminance = 0.299 R + 0.587 G + 0.114 B
  • Douglas-Peucker: recursively keep the farthest point beyond epsilon
  • The outline is placed in a view and feeds the same hull pipeline
FormFlow22 / Line Stitching

Line stitching

Hand strokes do not close exactly. A nearest-end search proposes closing or joining.

WhatCloses loops and joins nearby strokes.WhyHands never land exactly, and the hull needs closed outlines.For whomEvery user drawing outlines by hand.
JOIN_TOL = 0.12 world units (workspace 2.4 wide) MIN_LOOP_LENGTH = 0.5 suggestFor(items, stroke): close : gap(first, last) < tol, length >= 0.5 join : min over ends of other lines of |e_a - e_b| < tol pick the smaller gap joinedCopy: end points replaced by their midpoint (no gap, no duplicate point) stitchAll: join and close everything possible all operations return NEW items, so they are undoable

Why

  • Visual hull needs closed outlines
  • Prompt is answered by pinch or key (Y / N)
  • Only free and straight lines join; solids are already complete

FormFlow25 / Limitations

Limitations and future work

An ideation tool, not manufacturing-grade CAD.

Limitations

  • A visual hull is the maximal shape consistent with the silhouettes: concavities and hidden features are filled
  • Silhouettes that disagree give a wrong or empty hull (reported)
  • Depth in free 3D drawing is a user-controlled plane, not metric
  • Hand landmark quality depends on lighting, occlusion, background, resolution
  • Voxel resolution n = 64 limits detail (O(n3))

Future work

  • Photo consistency or colour cues to carve concavities
  • Adaptive / octree voxels for higher resolution
  • Numeric dimension input and constraints
  • Save and load scene projects
  • Learned depth cue for free-space drawing
